# ADR-003: Стратегия построения UI/UX, дизайн-системы и интеграции shadcn/ui

* **Статус:** Принято (Accepted)
* **Дата:** 2026-10-06
* **Контекст:** Разработка интуитивного, адаптивного и современного интерфейса для платформы студенческого рекрутинга с поддержкой светлой/темной тем, состояний загрузки (Skeletons) и пустых списков (Empty States).

---

## 1. Контекст и проблематика

Платформа ориентирована на молодую техническую аудиторию (студентов IT-специальностей) и требовательных рекрутеров. Интерфейс должен отвечать следующим критериям:
1. **Визуальная эстетика и премиальный вид:** уход от устаревших «тяжелых» таблиц классических джоб-бордов в сторону легкого, карточного и модульного интерфейса.
2. **Адаптивность (Mobile First):** студенты активно пользуются смартфонами для мониторинга статусов откликов и поиска вакансий между лекциями.
3. **Доступность (A11y):** соответствие стандарту WCAG 2.1 AA (контрастность, навигация с клавиатуры, поддержка скринридеров).
4. **Контроль над исходным кодом компонентов:** отсутствие закрытых UI-библиотек («черных ящиков»), возможность кастомизации любого примитива под академические бейджи, графики GPA и канбан-доски.

---

## 2. Рассмотренные альтернативы

### Вариант А: Сторонняя готовая компонентная библиотека (MUI / Ant Design)
* *Плюсы:* Готовые сложные виджеты «из коробки».
* *Минусы:* Тяжелый рантайм CSS-in-JS, сложность глубокой перестилизации под кастомный бренд, визуальная перегруженность корпоративным стилем начала 2010-х годов.

### Вариант Б: Tailwind CSS + shadcn/ui (Radix UI Primitives)
* *Плюсы:*
  * Код компонентов копируется прямо в проект (`src/components/ui/`), обеспечивая 100% контроль над разметкой и стилями.
  * Доступность из коробки (Radix UI отвечает за ARIA-атрибуты, фокус-ловушки и работу с клавиатурой).
  * Нулевой runtime overhead: Tailwind CSS генерирует минимальный статический CSS файл.
  * Удобная поддержка темной темы через CSS-переменные в формате HSL.
* *Минусы:* Требуется первоначальная настройка конфигурации и ручная сборка композитных компонентов (что легко решается качественной структурой проекта).

---

## 3. Решение

Принят **Вариант Б (Tailwind CSS + shadcn/ui)**:

### 3.1. Архитектура дизайн-системы
1. **Базовые токены (Design Tokens):**
   * Все цвета, радиусы скруглений и тени определяются через CSS-переменные в `src/app/globals.css`.
   * Цветовая палитра: глубокий темно-синий/индиго (`slate/indigo`) в сочетании с изумрудными акцентами успеха для офферов (`emerald`) и янтарными предупреждениями (`amber`).
2. **Поддержка тем оформления:**
   * Интеграция `next-themes` со стратегией `class` на теге `<html>`.
   * Автоматическое переключение: Светлая, Темная, Системная.
3. **Иконографика:**
   * Библиотека `lucide-react` как единый стандарт векторных иконок.

### 3.2. Специализированные паттерны взаимодействия (UX Patterns)
* **Академические бейджи (Academic Badges):**
  * Цветовая дифференциация GPA (например, GPA ≥ 4.5 — бейдж с золотым/изумрудным акцентом «Высокий академический балл»).
  * Бейджи курсов и направлений подготовки («3 курс Бакалавриата», «ФКН ВШЭ»).
* **Состояния загрузки (Skeletons):**
  * Для всех динамических блоков (список вакансий, карточка резюме, канбан-колонка) реализуются специализированные скелетоны (`VacancyCardSkeleton`, `ProfileSkeleton`), предотвращающие сдвиги макета (CLS).
* **Пустые состояния (Empty States):**
  * Каждая страница и список имеют дружелюбное пустое состояние с поясняющей иллюстрацией/иконкой и четким призывом к действию (CTA), например: «Пока нет откликов. Опубликуйте вакансию в студенческих каналах или измените требования».
* **Интерактивный Kanban откликов:**
  * Доска кандидатов с drag-and-drop или быстрыми селекторами смены этапа (`Новый` → `Скрининг` → `Тестовое` → `Интервью` → `Оффер` / `Отказ`).

---

## 4. Последствия

* Высокая скорость верстки адаптивных страниц.
* Единый согласованный визуальный стиль во всех сценариях студента и работодателя.
* Отсутствие проблем с доступностью и производительностью рендеринга.
