# ADR-001: Выбор технологического стека, архитектуры репозитория и СУБД

* **Статус:** Принято (Accepted)
* **Дата:** 2026-10-06
* **Контекст:** Разработка MVP платформы студенческого рекрутинга UniTalent с высокими требованиями к скорости вывода на рынок (Time-to-Market), типобезопасности и качеству UX/UI.

---

## 1. Контекст и проблематика

Для реализации платформы студенческого рекрутинга требуется стек, способный обеспечить:
1. Быстрый старт MVP без избыточных накладных расходов на сетевое взаимодействие между разрозненными микросервисами.
2. Сквозную строгую типизацию TypeScript от схемы базы данных до компонентов пользовательского интерфейса.
3. Качественный SEO для страниц вакансий и профилей компаний (SSR / Static generation).
4. Реляционную модель данных со сложными связями (студенты, ВУЗы, специальности, проекты, GPA, вакансии, отклики, этапы воронки).
5. Надежную аутентификацию с разделением прав доступа (студент, работодатель, администратор).

---

## 2. Рассмотренные альтернативы

### Вариант А: Раздельный бэкенд (FastAPI / NestJS) + SPA (Vite / React)
* **Плюсы:** Четкое разделение ответственности, независимый деплой фронтенда и бэкенда.
* **Минусы:** Необходимость синхронизации DTO/схем между двумя репозиториями (или поддержка monorepo инструментами Nx/Turborepo), двойной бойлерплейт API-клиентов, плохой SEO из коробки для SPA без SSR.

### Вариант Б: Модульный Full-Stack Next.js (App Router, TypeScript) в едином репозитории
* **Плюсы:**
  * Единый язык (TypeScript) и возможность шерить Zod-схемы валидации между клиентом и сервером.
  * Server Actions устраняют необходимость в ручном написании бойлерплейта REST-контроллеров и клиентов fetch/axios.
  * Нативная поддержка Server-Side Rendering (SSR) для вакансий (критично для поисковиков) и мгновенный Fast Refresh в разработке.
  * Минимальная инфраструктурная сложность для MVP.
* **Минусы:** При масштабировании до сотен разработчиков требуется дисциплина слоев (которая компенсируется строгими правилами в `docs/agents.md`).

---

## 3. Решение

Принят **Вариант Б**:
1. **Фреймворк приложения:** **Next.js 15+ (App Router)** с полным переходом на TypeScript и строгий режим (`strict: true`).
2. **Слой данных и СУБД:** **PostgreSQL 16** в связке с **Prisma ORM**.
   * *Обоснование:* PostgreSQL обеспечивает строгую реляционную целостность, поддержку JSONB (для гибких структур академических наград и технологий), мощные индексы для фильтрации по числовым полям (GPA, курс, вилка стипендий). Prisma дает полную типобезопасность запросов и декларативные миграции.
3. **Бизнес-логика и валидация:** **Zod** в качестве единственного источника валидации схем, используемый как на клиентских формах (с React Hook Form), так и в Server Actions.
4. **Аутентификация:** **NextAuth.js (Auth.js)** с поддержкой email/password (bcrypt) и OAuth-провайдеров, с хранением сессий и ролей в JWT/базе данных.
5. **Контейнеризация инфраструктуры:** **Docker Compose** для локального запуска PostgreSQL.

---

## 4. Последствия и риски

### Положительные последствия:
* Максимальная скорость разработки MVP за счет устранения дублирования типов.
* Нулевые задержки сетевого обмена внутри монолита.
* Упрощенный CI/CD пайплайн (один билд и один артефакт запуска).

### Управление рисками:
* *Риск смешивания серверного и клиентского кода:* Предотвращается архитектурным разделением (`src/components` vs `src/server/services`) и строгим соблюдением соглашений `docs/agents.md`.
